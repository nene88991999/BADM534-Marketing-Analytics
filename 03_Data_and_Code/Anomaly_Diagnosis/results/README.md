# Monitoring Results

Generated by the two programs in the parent folder from original synthetic inputs. The [data dictionary](../DATA_DICTIONARY.md) defines the sample and score. Both methods evaluate the same 1,080 later store-minutes and the same three 20-minute event windows.

| File | Contents |
| --- | --- |
| `reference.csv` | Training-only center and scale for each store, phase, and feature |
| `test_scores.csv` | All test observations, both scores, and missing-feature counts |
| `detection_summary.csv` | Thresholds, confusion counts, precision, recall, and wholly nominal-run denominators |
| `incident_metrics.csv` | First matched alert interval, onset detection delay, and interval intersection-over-union |
| `variable_rankings.csv` | Per-variable deviations averaged within true or matched alert intervals |
| `evidence_packets.json` | Nine observation-and-alert packets without incident answers |
| `timing_metrics.csv` | Precise, delayed, and full-window predictions for the fixed [40,60) event |
| `missingness_comparison.json` | Earlier imputations under two possible future observations; original versus compressed row positions |

Both rules detect all 60 event minutes. The mean rule flags nine additional minutes and the maximum rule seven. Each flags two of 720 minutes in wholly nominal runs, distributed across two of six runs. Five additional alert minutes in the payment run are a delayed support response after the imposed failure ends. Detection of the campaign demonstrates unusualness without an operational failure.

For the payment case, both rules yield [40,65), with interval intersection-over-union 0.80 against [40,60). Support contacts rank first within both windows. The separate exact timing comparison gives values 1.00, 0.60, and 1/6 despite all predictions receiving any-overlap credit. No result measures a real retailer, a causal effect estimated from observations, or an LLM's accuracy.
