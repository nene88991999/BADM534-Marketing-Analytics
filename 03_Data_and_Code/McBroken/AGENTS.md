# Agent Guide for McBroken Examples

Read the root agent guide, this folder's README, and DATA_DICTIONARY.md. Start with the managerial question and the observation process.

- Use **recorded order unavailability** for the course outcome. The `is_broken` field is not verified repair-log evidence.
- Read the aggregate tables and results before the three-million-row source panel. Use the source hashes and commit IDs for provenance.
- Distinguish a missing US date, a sparse snapshot, a missing same-key target, and an observed available record.
- Original address keys can change spelling. Exact coordinate counts diagnose possible aliases; they are not verified counts of physical restaurants. Do not merge keys automatically on coordinates.
- Match next calendar dates explicitly. Preserve the eligible-origin denominator and report usable-label coverage with forecast scores.
- Fit only on earlier target dates. Full-year `n_days`, `last_seen`, and future snapshot coverage are not origin-time predictors.
- The policy program computes descriptive country contrasts. Do not call its differences a causal policy effect or invent significance tests based on independent stores.
- The five source programs match the full Python blocks in M2 §2.16, M6 §6.16, and M7 §7.18. Update both when editing and run `scripts/check_lecture_code.py` from the repository root.
- `run_all.py` uses local teaching tables and requires no network. The original collection notebook and network retrieval scripts have separate provenance and were not rerun for this adaptation. Do not activate their scheduling template unless requested.
