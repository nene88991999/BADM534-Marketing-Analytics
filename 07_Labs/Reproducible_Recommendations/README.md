# Reproducible Product-Screening Recommendations

Optional, ungraded practice for M1 §1.15 and M8 §8.25. Any editor with a terminal and Markdown support is sufficient. Suzuri is an optional environment. This exercise establishes no submission, deadline, or required software.

A product manager has a synthetic concept comparison and asks which concepts warrant human research. Prepare a recommendation that another analyst can reproduce and interpret after receiving the project folder. The [inputs and complete Python](../../03_Data_and_Code/Reproducible_Recommendations/README.md) are public course examples. All personas and reference panels are invented; no model account is needed.

## Calculation and Interpretation

Run from the course root:

```bash
python3 03_Data_and_Code/Reproducible_Recommendations/reproduce_recommendation.py
python3 -m unittest discover -s 03_Data_and_Code/Reproducible_Recommendations -p 'test_*.py' -v
```

Read the [generated recommendation](../../03_Data_and_Code/Reproducible_Recommendations/results/recommendation.md) beside its [evidence file](../../03_Data_and_Code/Reproducible_Recommendations/results/evidence.json), and calculate the p01 rating from weights `(0, .05, .15, .30, .50)`. Compare `(4.25 + 3.70)/2` with `(2 × 4.25 + 3.70)/3` to identify which weighting rule changes after an identical repeat. Use the repeat-count figure, holding both persona ratings fixed, to explain why the intended unit must determine the denominator.

Next assess this deliberately unsupported statement: “The pooled system achieves a high distribution score, so concepts A and B should launch.” Identify the unresolved shortlist, the reference-based construction of the candidate pattern, and the absent customer-demand evidence. A numerical claim and an action recommendation require different support. The reversed pattern selects F and E and retains zero of the reference top two. Explain why its measured zero differs from the pooled pattern's undefined recall.

If using an assistant, provide the synthetic evidence file and ask: “Explain the two refill means and trace the selected identifiers to the comparison. Preserve missing values and distinguish invented inputs from human validation. Identify evidence needed before a launch recommendation.” Compare each numerical assertion against the file and assess the interpretation yourself. The supplied report is generated by a deterministic program; it is not an observed response from a model.

## Execution and File Location

Run the program again from its own folder. Compare the resulting evidence and report. Move a copy of the project to a different path, retaining both example folders and the linked lecture figure, and repeat. The tests also exercise three working directories inside a temporary relocated copy. Paths, dependencies, and outputs should be explicit. If adapting the exercise to a notebook, record the kernel's working directory and restart it before the final run.

In a disposable copy, change a saved result without changing the inputs. The program should stop because recomputation disagrees with the table. Explain why copying the same mistake into both the calculation and the saved table would require an independent arithmetic check to detect it.

## Rendering and Navigation

Inspect the dollar amounts, equation, five-category table, and figure in the Markdown report. With Pandoc available, a single-page HTML preview can be generated from the report folder:

```bash
pandoc recommendation.md --from=markdown+tex_math_dollars --standalone --mathml --metadata pagetitle='Product-Screening Recommendation' --output recommendation.html
```

Check that `$500` and `$25` remain currency, the expected-rating equation renders as mathematics, category weights sum to one, and the figure remains legible. Follow each file link from the exported page. Relative paths depend on keeping the linked files in the same relative locations. A link to a Markdown file may open source text; a future site builder must explicitly map source pages and section anchors to their HTML destinations.

If testing Suzuri, create disposable notes containing an ordinary Markdown link and a `[[Note#Heading]]` link. Export both and inspect the destinations. The reviewed Suzuri 0.7.0 preprocessing function converts the wikilink to display text. For a note embed, remove the referenced section and inspect the export message and resulting content. These optional application tests have not been executed in Suzuri; the [source review](../../01_Resources/30_Research_Writing_and_Coding/SOURCE_REVIEW.md) records static evidence and version details.

## Public Release

Inspect `git status --short`, `git diff`, and the explicitly staged diff. Check new untracked files separately. Bibliography software can add attached PDFs; determine their redistribution rights before including them. Keep the exact inputs and executed calculation available with a released recommendation. A file hash checks identity, and a Git commit records a version. The analyst remains responsible for the sample, inference, and use of the result.

Keep separate conclusions for numerical agreement, interpretation, rendering, navigation, and publication. A successful export does not establish that a recommendation is justified or that a course wiki is deployed.
